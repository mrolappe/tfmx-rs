**Full brief: [`docs/m5-plan.md`](docs/m5-plan.md)** — read it before starting any phase below. It
carries the context, the six recorded decisions with their rationale, the architectural
constraints, the 7V posture, the delegation rules and each phase's subtask/model breakdown. The
list here is the checkbox tracker only.

Two findings made during planning shape the whole milestone, both verified, neither obvious:

- **A reference Paula register log looks obtainable.** WinUAE 6.1.0 (Stefan Reinauer's
  cross-platform fork) is installed at `/Applications/WinUAE.app`, has a `Memwatch` debugger and
  symbolic `AUD0LCH/LCL/LEN/PER/VOL`. Paula's audio registers are memory-mapped at
  `$DFF0A0–$DFF0DF`, so a write-watch there *is* a reference log — captured from the **TFMX editor**
  the user already trusts, with no GPL replayer involved. This would be the project's first cheap
  oracle. Unverified risk: whether memwatch can *log* rather than *break*, and be captured to file.
- **Macros are key/velocity zone maps.** `docs/opcodes.md:176-177` — `$1C <Splitkey>` branches on
  note, `$1D <Splitvol>` on volume. Resolving those statically gives, per macro, a
  `(note range, velocity range) → sample region` table that maps **one-to-one onto SFZ's
  `lokey`/`hikey`/`lovel`/`hivel`**. That one table feeds MIDI mapping, sampler export, sample
  export and tracker export alike. It is the spine of the milestone.

update the idea ledger, append problems *and mistakes* to `docs/m5-session-log.md`, update the
Status block to name the next phase, commit, push, **stop**.

## Known risks

| Risk | Mitigation |
|---|---|
| Timing model (CIA timer vs. 50 Hz divider) — the most common failure, and it sounds like a working player at the wrong speed rather than like a bug | 50 Hz path first, CIA path added separately and verified by ear |
| Two header layouts | Both from the start; detection is the zero check found in 0.3 |
| GPL contamination | Reference players are executed, never read |
| Aliasing from naive resampling | Accepted for M1, marked with a `ponytail:` comment |
